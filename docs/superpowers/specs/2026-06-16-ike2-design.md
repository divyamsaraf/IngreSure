# IKE-2 (IngreSure Knowledge Engine v2) — Design Spec

**Status:** Implemented — shadow-ready (June 2026). Primary cutover gated on soak metrics.
**Date:** 2026-06-16
**Owner:** Architecture
**Related:** High-level decision record at `.cursor/plans/ingredient_knowledge_architecture_cc85a538.plan.md`; task-level build steps at `docs/superpowers/plans/2026-06-16-ike2-implementation.md`

---

## 1. Overview

IKE-2 is a greenfield ingredient resolution + compliance engine that runs **in parallel** with the current resolver under a feature flag (`IKE2_MODE`). It resolves raw ingredient strings to canonical groups, evaluates dietary/allergen restrictions deterministically, and emits an auditable verdict. It is promoted to primary only after it passes golden (labeled) and shadow (live-traffic) gates with **zero false-Safe regressions**.

It replaces neither the database nor the running system on day one. New `ike2_*` tables and a new `backend/core/knowledge/ike2/` module are added alongside the legacy path; the legacy `ingredient_*` tables and resolver keep serving users until cutover.

## 2. Goals / Non-goals

### Goals
- Resolve raw input (typed, OCR, barcode-derived) to a canonical group with explicit provenance and confidence.
- Deterministic compliance verdicts — no probabilistic verdicts on the hot path.
- **Zero false-Safe outputs** (see §3). Uncertainty degrades to Depends, never to Safe.
- Support bulk ingestion and incremental updates from arbitrary sources (offline ETL), and new regions/languages via aliases.
- Shadow-mode parallel run with measurable, ground-truth-based cutover gates.

### Non-goals (v1)
- Runtime fuzzy matching (offline merge proposals only).
- LLM in the resolution/verdict path (LLM is an enrichment hint into the review queue only).
- Reading a Postgres cache on the hot path (Redis + in-process LRU only).
- `parent_group_id` flag inheritance (deferred to v2).
- Replacing the OCR/barcode scan pipeline (IKE-2 consumes its output; integration documented, not rebuilt).

## 3. Correctness Contract (the core invariant)

Two failure types are **not** equal:
- **False Safe** (SAFE when truth is Avoid) — catastrophic (allergy/diet harm). **Budget = 0.**
- **Over-caution** (Depends/Avoid when it might be fine) — annoying, not dangerous. Soft budget.

> **Invariant (fail-closed):** the system MUST NEVER emit a firm SAFE verdict from uncertain or untrusted knowledge. When in doubt, it degrades to WARN/Depends.

Achievable guarantee: **100% safety (zero false Safe)**, accepting some over-caution. Enforcement is defense-in-depth:

| Mechanism | Rule |
|-----------|------|
| DB CHECK constraints | `insect_implies_animal`, `egg/dairy/fish/shellfish_implies_animal`, `verified_requires_source`, dual-origin requires uncertainty flag |
| Knowledge-state gate | rules fire only if `group.knowledge_state >= rule.min_knowledge_state`; UNCLASSIFIED never yields SAFE |
| Trust gate | `*_inferred` flags + non-`static`/non-`high` sources never trusted for SAFE (`is_trusted_for_compliance`, `backend/core/evaluation/resolution_trust.py`) |
| Truth Anchor | ~80 hardcoded safety-critical facts override every lower layer |
| Uncertainty propagation (C3) | UNCLASSIFIED → never SAFE; DISCOVERED PASS → WARN; `verdict_cap` caps inherently-uncertain groups at WARN |
| Aggregate (C4) | most severe wins: FAIL > WARN > UNCERTAIN > SAFE |
| Resolution miss | unknown → UNCERTAIN + enqueue; never SAFE |
| **Ambiguous alias** | >1 candidate and no region match → UNCERTAIN; never silent auto-pick |
| E-numbers | no API resolution; static/DB only |

**Measurement:** the safety budget is measured against **human-labeled ground truth**, never against legacy output (legacy has known bugs; IKE-2 is expected to diverge from it on those).

## 4. Verdict vocabulary (decided)

IKE-2 computes a 4-tier verdict internally and the response layer maps it to the existing 3-tier contract (no frontend/stream-protocol change):

| Internal | External (existing) | UI card |
|----------|---------------------|---------|
| FAIL | NOT_SAFE | Avoid |
| WARN | UNCERTAIN | Depends |
| UNCERTAIN | UNCERTAIN | Depends |
| SAFE | SAFE | Safe |

WARN never collapses to SAFE. B2B API may later expose the raw 4-tier via `schema_version`.

## 4A. Restriction severity, traces, caution, and presentation modes (decided)

**One deterministic core, audience-specific presentation.** The compliance engine computes a single rich result; it never forks verdict logic by audience (two policies = two truths = drift = false-Safe risk). Only the response layer varies per consumer.

### Restriction severity (new profile concept)
Each profile restriction carries `severity ∈ {medical, preference}`. `medical` = allergy/medical (peanut allergy, celiac); `preference` = diet/choice (vegan, no-onion). **Unknown/unset severity defaults to `medical` (fail-closed).** This requires a profile-side field; if the current profile model has no severity, add it with default `medical` and a migration.

### Rich compliance result (single source of truth)
The engine emits, per evaluated restriction: `matched_contains[]` (definite), `matched_may_contain[]` (trace), `severity`, the internal 4-tier `verdict`, and `caution_reasons[]`. Computed fail-closed; this result is identical regardless of caller.

### Trace (`may_contain`) policy
| Case | Internal verdict | Note |
|------|------------------|------|
| `contains X` (matches restriction) | FAIL | definite |
| `may_contain X` + **medical** | FAIL | badge must protect a non-reading allergic user |
| `may_contain X` + **preference** | WARN | + statement: "may contain {X} (cross-contamination); avoid to be strict, usually fine for a diet preference" |
| unknown severity | treated as **medical** | fail-closed |

Traces are **always** surfaced in the audit, even when they don't change a preference verdict.

### Caution annotation (not a verdict tier)
`caution_reasons[]` carries codes: `may_contain_trace`, `inherent_uncertainty` (natural flavors / verdict_cap), `unverified_knowledge` (DISCOVERED/AUTO_CLASSIFIED), `ambiguous_alias`, `untrusted_source`. Caution annotates *why* a result is Depends/Avoid/uncertain. **It never upgrades a verdict to SAFE.**

### Presentation modes
- **B2B (API/backend) — strict + full data:** default treats `may_contain` as a trigger (→ NOT_SAFE); returns the full breakdown (`matched_contains`, `matched_may_contain`, `severity`, raw 4-tier via `schema_version`, `caution_reasons`) so the integrator applies its own policy.
- **B2C — severity-aware friendly:** applies the trace table above; renders `caution_reasons` as an icon + plain-language statement.
- **Invariant for all modes:** never SAFE when a matching `contains`/trace is present-or-uncertain; unknown severity → medical.

## 4B. Additional edge-case rules (decided)

**Alcohol.** Store `alcohol_role ∈ {none, ingredient, fermentation_trace}` on the group (do not infer % at runtime — reliable percentages are rarely available).
- `ingredient` (wine, beer, spirits, vanilla extract, ethanol) → **FAIL** for alcohol-restricted profiles.
- `fermentation_trace` (vinegar, soy sauce, bread, ripe fruit) → **WARN** + statement, caution `inherent_uncertainty`.
- Alcohol present but role unknown → **WARN** (never SAFE).

**Unresolvable compound terms** ("spices", "seasoning", "natural flavors"): the compound resolves but hidden children are unknown → **WARN/UNCERTAIN** via `verdict_cap=WARN`, caution `inherent_uncertainty`. Never SAFE — these can hide onion/garlic (Jain) or allergens.

**Region for B2B.** Region is a **recommended request param**. With no region: unambiguous aliases still resolve; ambiguous aliases → **UNCERTAIN** + caution `ambiguous_alias`. Region is never inferred.

**Multi-restriction profiles** (e.g. vegan + peanut allergy): evaluate each restriction independently, retain the per-restriction breakdown in the result, then **C4 aggregates most-severe across all restrictions × all ingredients**.

**Trace/flag provenance** (gates verdict *strength*, consistent with `is_trusted_for_compliance`):
- **Trusted** trace (label / static / VERIFIED) → severity rule (medical→FAIL, preference→WARN).
- **Untrusted/inferred** trace (low-confidence API/LLM) → **UNCERTAIN (Depends)** + caution `untrusted_source`; never a hard Avoid, never SAFE.
- An untrusted source can never *remove* a trace flag — only fail to strengthen it.

**Stakeholder rationale:** medical users get badge-level protection on real risks; preference users avoid false-Avoid noise; B2B gets full structured data + a strict default to apply its own policy; all consumers share one underlying truth (no divergence) plus transparent `caution_reasons`.

## 5. Data model

New tables (greenfield, prefix `ike2_`). Full DDL is produced in the implementation plan; this section is the contract.

### 5.1 `ike2_ingredient_groups` — canonical identity + compliance truth
- Identity: `id UUID`, `canonical_name TEXT` (stable internal handle; **not** region/language-specific), `slug`.
- Origin: `animal_origin`, `plant_origin`, `synthetic`, `fungal`, `insect_derived` (bool).
- **Allergen flags (DECIDED: full booleans):** `egg_source`, `dairy_source`, `gluten_source`, `soy_source`, `sesame_source`, `peanut_source`, `tree_nut_source`, `fish_source`, `shellfish_source`, `mustard_source`, `celery_source`, `lupin_source`, `sulphite_source`. Booleans (not a single enum) because one ingredient can be multiple allergens at once — a single enum silently drops the others (a false-Safe hole).
- Meat/diet: `animal_species TEXT` retained **only** for halal/kosher meat-species rules (e.g. pork); `root_vegetable`, `onion_source`, `garlic_source`, `fermented`, `alcohol_content NUMERIC`, `alcohol_role TEXT` (`none|ingredient|fermentation_trace`).
- Knowledge: `knowledge_state` enum (`UNCLASSIFIED < DISCOVERED < AUTO_CLASSIFIED < VERIFIED < LOCKED < DEPRECATED`), `classification_method`, `verdict_cap` (nullable; e.g. WARN), `primary_source_url`, `uncertainty_flags TEXT[]`.
- Lifecycle: `superseded_by UUID NULL`, `created_at`, `updated_at`, `version`.
- CHECK constraints enumerated in §3.

This is a superset of the existing `Ingredient` dataclass (`backend/core/ontology/ingredient_schema.py`), adding the missing allergen booleans (`fish_source`, `shellfish_source`, `mustard_source`, `celery_source`, `lupin_source`, `sulphite_source`, splitting `nut_source` → `peanut_source`/`tree_nut_source`) and the knowledge-lifecycle columns.

### 5.2 `ike2_ingredients` — named forms per group
Named substance forms linked to a group (`group_id`), with `normalized_name`, source provenance, `superseded_by`.

### 5.3 `ike2_aliases` — routing layer (raw string → ingredient)
`normalized_alias`, `ingredient_id`, `alias_type` (`common|brand|regional|misspelling|e_number|cas_number|fda_number|iupac_name`), `language`, `region`, `match_confidence` (`exact|high|possible`), `source`.

**Uniqueness (decided):**
- Global unique for unambiguous types only: `e_number, cas_number, fda_number, iupac_name`.
- Region-scoped unique for everything else: `UNIQUE (normalized_alias, COALESCE(region,'GLOBAL'))`.

### 5.4 `ike2_alias_disambiguation` — known conflicts
`(normalized_alias, context_region, ingredient_id, priority, notes)`. Resolution rule: pick by `context_region`; **no region match and no seeded GLOBAL winner → UNCERTAIN** (never silent pick). A GLOBAL winner is seeded only when one meaning is globally dominant and the minority meaning is not safety-relevant.

### 5.5 `ike2_restriction_rules` — deterministic rule config
`category`, `field`, `operator`, `value`, `action` (FAIL/WARN), `min_knowledge_state`, `region`, `version`. Loaded from `data/restrictions.json` via ETL.

### 5.6 `ike2_resolution_cache` — write-only audit/analytics
Populated async after resolution. **Never read on the hot path.**

### 5.7 `ike2_unknown_queue` — discovery + enrichment
`normalized_key`, frequency, raw enrichment JSONB, classification decision, status.

### 5.8 Shadow + ops tables
- `ike2_shadow_diffs` — per-request legacy-vs-IKE-2 comparison (see §8).
- `ike2_group_merges` — merge audit with `rollback_snapshot JSONB`.
- `ike2_staging.*` — staging mirrors without UNIQUE constraints; `stg_rejects` quarantine.

## 6. Resolution pipeline

Input is decomposed in the **Input Layer** (sanitize → decompose/compound-expand → `normalize_ingredient_key`). Per normalized atom, resolution runs 5 layers (collapsed from the original 7 for simplicity/safety):

1. **L1 Truth Anchor** — hardcoded dict; wins over everything for listed keys.
2. **L2 Cache** — in-process LRU + Redis (`backend/core/...` existing redis layer). Hot path only.
3. **L3 DB alias** — `ike2_aliases` scoped lookup, then `ike2_alias_disambiguation` by region.
4. **L4 Regional translate** — map regional/native term → canonical alias, re-enter L3.
5. **L5 APIs → unknown queue** — USDA/OFF/PubChem/Wikidata; high-confidence non-E-number may resolve, otherwise enqueue as UNCERTAIN. LLM is a sub-step of queue enrichment, never a runtime resolver.

Single-query resolution via view/RPC `ike2_v_alias_resolution` (alias→ingredient→group in one round-trip, filtering `superseded_by IS NULL` and `knowledge_state != DEPRECATED`).

**Output:** a `ResolvedIngredient` carrying the group, `source`, `confidence_band`, `trusted` (from `is_trusted_for_compliance`), and `resolution_layer`.

## 7. Compliance + response

**Compliance (C1–C4):**
- C1 Truth Anchor re-check.
- C2 evaluate `ike2_restriction_rules` for the active profile (gated by `min_knowledge_state`).
- C3 uncertainty propagation (UNCLASSIFIED→never SAFE; DISCOVERED PASS→WARN; apply `verdict_cap`; untrusted resolution→never SAFE).
- C4 aggregate (most severe wins).

**Response:** an `IdentityAssembler` provides one `triggered?` function shared by compliance, audit, and UI — this permanently fixes the Yam-class audit/identity divergence (where an excluded-but-displayed ingredient produced an inconsistent card). Emits audit trail, badges, disclaimer, and maps internal 4-tier → external 3-tier (`schema_version`-aware).

## 8. Shadow mode + cutover

`IKE2_MODE` (in `backend/core/config.py`): `off | shadow | primary | fallback`.
- `shadow` — both run; legacy drives user output; every request logged to `ike2_shadow_diffs`.
- `primary` — IKE-2 drives; legacy runs for comparison.
- `fallback` — IKE-2 primary, auto-fallback to legacy on resolver error.

**Cutover gates (measured vs ground truth, not legacy):**
- HARD: 0 cases where `ike2=SAFE` and `expected = NOT_SAFE` on the labeled golden corpus and on the 7-day shadow soak.
- Triage: legacy mismatches bucketed {IKE-2 correct / equal / IKE-2 wrong}; only "IKE-2 wrong on safety" blocks.
- Latency: p99 ≤ legacy + 20ms (cache hit) and ≤ legacy + 50ms (Redis-miss → DB). Resolver error < 0.01%.

## 9. Data engineering / ETL

Sources are pluggable via a **source registry** (declares trust tier + default `knowledge_state`). Pipeline: `source adapter → ike2_staging → VALIDATE (CHECK constraints) → dedup/merge proposals → human review → MERGE to prod`.

- **Idempotency:** every job keyed by `(source, normalized_name)` or `(source, normalized_alias, region)`; re-run safe (upsert).
- **Reject quarantine:** rows failing CHECK go to `stg_rejects` with a report; the batch is not aborted and rows are not silently dropped.
- **Source-conflict policy (offline only):** precedence Truth Anchor > human VERIFIED/LOCKED > regulatory > curated ontology > USDA > OFF/crowd > LLM. On conflict of a compliance flag: take **most restrictive**, drop `knowledge_state`, raise review row; never overwrite a higher tier. Runtime reads the reconciled row (zero hot-path cost).
- **Load order:** restrictions → Truth Anchor → ontology → regional names → bulk transforms (staging→proposals) → dynamic learns → conflict report.
- **Reuse:** port `backend/core/knowledge/ingest.py` and `backend/scripts/merge_all_sources.py` logic to target `ike2_*`; keep offline edit-distance for merge **proposals only**.

### 9.1 Implemented bulk-injection approach (`core/knowledge/ike2/etl/bulk_inject.py`)

The shipped CLI uses **direct-to-live, capped by `knowledge_state`** rather than the staging→human-review→merge gate above. This is safe and intentional:

- Nothing bulk-loaded reaches `VERIFIED`/`LOCKED` (source registry caps crowd sources at `DISCOVERED`, curated/regulatory at `AUTO_CLASSIFIED`), so an unreviewed row **cannot produce SAFE** (compliance degrades `DISCOVERED`→WARN, `UNCLASSIFIED`→UNCERTAIN) and cannot satisfy a rule's `min_knowledge_state` for a definite FAIL it isn't entitled to.
- Writes target `ike2_*` only; the legacy `ingredient_*` tables production reads are untouched.
- Pipeline per row: `source adapter → VALIDATE (CHECK mirror) → reconcile (most-restrictive) → upsert live`. Idempotent keys as above.
- **Adapter safety:** free-text `nut_source` is parsed to specific `peanut_source`/`tree_nut_source` flags (ambiguous → both, fail-closed); `alcohol_role` is derived (explicit alcohol → `ingredient`, fermented → `fermentation_trace`). Both guard against false-SAFE.
- **Deviations from the gate model (deferred, non-safety):** rejects are written to a JSON report file rather than `ike2_staging.stg_rejects` (the staging schema is not exposed over PostgREST), no raw landing in `ike2_staging`, and no group-level `source_tier` column (most-restrictive already blocks false-SAFE regardless of tier). These are auditability/curation-quality follow-ups.

## 10. Testing strategy (TDD)

Every Correctness-Contract guarantee is a named failing test written **before** implementation. Minimum set:
- `test_truth_anchor_overrides_db`
- `test_unknown_ingredient_never_safe`
- `test_unclassified_never_safe`
- `test_discovered_pass_caps_to_warn`
- `test_verdict_cap_natural_flavor_warn`
- `test_aggregate_most_severe_wins`
- `test_ambiguous_alias_no_region_uncertain`
- `test_yam_in_region_vs_unknown_region`
- `test_dual_allergen_fish_and_shellfish_both_flagged`
- `test_enumber_no_api_resolution`
- `test_untrusted_resolution_never_safe`
- `test_medical_may_contain_fails` / `test_preference_may_contain_warns`
- `test_unknown_severity_defaults_medical`
- `test_alcohol_ingredient_fails_trace_warns`
- `test_compound_term_spices_caps_to_warn`
- `test_b2b_no_region_ambiguous_uncertain`
- `test_multi_restriction_aggregates_most_severe`
- `test_untrusted_trace_is_uncertain_not_avoid`
- ETL: `test_reject_row_quarantined_batch_continues`, `test_source_conflict_takes_most_restrictive`
- Golden corpus harness: labeled `(raw_input, profile, region, severity, expected_verdict, rationale, source_url)`. `expected_verdict ∈ {SAFE, UNCERTAIN, NOT_SAFE}` (external 3-tier); optional `expected_internal` (4-tier). Safety budget assertion = 0 cases of `SAFE` where expected `NOT_SAFE`.

## 11. Open decisions (resolved)
- Allergen model → **full booleans** (species kept for halal/kosher meat only).
- Verdict vocabulary → **internal 4-tier, external 3-tier map**.
- Alias uniqueness → **global for unambiguous types, region-scoped otherwise**.
- Ambiguous + no region → **UNCERTAIN**.
- Runtime fuzzy / LLM → **out** (offline / queue-only).
- Hot-path cache → **Redis + LRU; DB cache write-only**.
- Restriction severity → **`medical` vs `preference`; unknown defaults to `medical`** (fail-closed).
- `may_contain` traces → **medical→FAIL, preference→WARN+statement; always shown in audit**.
- Architecture → **one deterministic core; B2B strict+full-data, B2C severity-aware; presentation forks, verdict logic does not**.
- Caution → **`caution_reasons[]` annotation, not a verdict tier; never upgrades to SAFE**.
- Alcohol → **`alcohol_role`: ingredient→FAIL, fermentation_trace→WARN, unknown→WARN**.
- Compound terms ("spices"/"natural flavors") → **`verdict_cap=WARN`, never SAFE**.
- Trace provenance → **trusted trace applies severity rule; untrusted trace → UNCERTAIN, never Avoid/SAFE**.

## 12. Risks
- ETL mapping errors silently flipping a flag → mitigated by CHECK constraints + source-conflict policy + reject quarantine.
- Golden corpus under-coverage → size by category × knowledge_state × ambiguous alias, not a round number.
- Redis-miss latency spikes → cold-path latency gate + view/RPC single round-trip.
- Truth Anchor staleness → LOCKED state, reviewed list, version column.
